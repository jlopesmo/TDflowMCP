# ADR-0007 — Source-first development, packaging and testing

**Status:** Conditionally Accepted (owner, 2026-11-22); **validation gates S2 and S3 passed 2026-11-22** ([Phase 1A record](../research/2026-11-22-phase-1a-component.md)). Revision: the declared minimum and build target is **TD 2025.32440** (owner D10, 2026-11-22; previously a provisional 2025.33230+).

## Decision
1. `src/` text is the truth, and `TDflowMCP.tox` is built from it ([rules](../architecture/source-of-truth.md)).
2. **Build:** `tools/build_tox` runs inside TouchDesigner, launched with a generated disposable builder `.toe` (`tools/tdtoe.py`; no committed binary input). It constructs the COMP from `src/component/manifest.json`, embeds DAT contents with SHA-256, saves `build/TDflowMCP.tox`, and writes `TDflowMCP.json` (version, source digest, TD build used, sha256). **Proven in S2.** Reproducibility is defined by the source digest: raw `.tox` bytes differ per build only by TD metadata (`.build` timestamp, the playing local timeline's current frame).
3. **Dev mode:** DATs reference `src/` files through the `file` parameter for live editing. Release mode embeds the file contents.
4. **Tests:**
   - `tests/unit/`: stdlib `unittest` on CPython 3.11, covering protocol, policy, registry, audit, identity and approvals with no `td` import. Runs in CI.
   - `tests/td/`: an in-TD runner loads the built `.tox` into a disposable test project, runs integration tests and writes `build/td-test-results.json`. Runs locally or on a self-hosted runner, because TD licensing limits hosted CI.
   - `tools/check_docs.py`: ICM, link and ADR-status validation (exists since Phase 0).
5. **Versioning:** SemVer. The tool surface and the policy schema each carry their own version.
6. **Releases:** GitHub Releases from `main` only, after owner approval. **Filename amendment accepted by the owner on 2026-11-25.** The primary download is `TDflowMCP-vX.Y.Z.tox`, with a byte-identical `TDflowMCP.tox` compatibility download. Both names share one source-first build and the tagged release's `SHA256SUMS`, alongside `TDflowMCP.json` and `INSTALL.md`. For v1.0.0 and v1.0.1, verify the original receipt before adding the versioned binary and `SHA256SUMS-versioned`, and retain the original assets and annotated tags. Independently download and verify both names before recommending a new direct link.

## Alternatives
Commit the `.tox` binary as source (not diffable; merge conflicts); depend on Embody for externalization (coupling; open issue #194).

## Consequences
- Building requires a TD installation. The build records the TD build number used.
- **Build release artifacts on the declared minimum TD build (2025.32440)**, because a `.tox` saved by a newer build may not load in older builds. Test on both the minimum and the latest builds.
  - **Scoped exception for v1.0.0 only (owner D26, 2026-11-25; [roadmap](../icm/roadmap.md#d26--initial-public-release-scope-and-exception-owner-2026-11-25)):** the initial Windows release was tested on 2025.32440 only. The latest-build test is waived for this one release, and no compatibility with newer builds or macOS is claimed. Later releases follow the rule above.
  - **v1.0.1 (owner D28, 2026-11-25):** the owner gave the same scope for v1.0.1 (Windows, TouchDesigner 2025.32440, no TouchDesigner upgrade; [verification and release](../operations/verification-and-release.md#4-release-proposed)). The latest-build test was not run for it either.
- **Older-build feasibility (S5)** uses a separate dev build produced by the same builder **on 2025.32440**. It is never a release artifact.
- Any base `.toe` the builder needs is generated by script at build time, not committed as a binary input. If S2 shows that is impossible, a new ADR must govern the committed binary.
- TouchDesigner requires a license and typically an interactive, GPU-capable desktop session. A self-hosted runner therefore needs a logged-in Windows session and a licensed TD install. Hosted CI runs only the `td`-free unit tests.

## Validation gates
- **S2 (passed 2026-11-22):** an unattended `.tox` build from text with 15 custom parameters on 2025.32440, verified by builder self-checks and a two-build reproducibility comparison.
- **S3 (passed 2026-11-22):** the in-TD runner loads the built `.tox` into a disposable project, drives it, and emits JSON results (`build/td-test-results*.json`).
- If either fails, this ADR reopens before any production `.tox` work.
