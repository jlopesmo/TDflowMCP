# ADR-0007 — Source-first development, packaging and testing

**Status:** Proposed (2026-11-22).

## Decision
1. `src/` text is the truth, and `TDflowMCP.tox` is built from it ([rules](../architecture/source-of-truth.md)).
2. **Build:** `tools/build_tox` runs inside TouchDesigner, launched with a startup script against an empty build `.toe`. It constructs the COMP from `src/component/manifest.json`, embeds DAT contents, saves `build/TDflowMCP.tox`, and writes `TDflowMCP.json` (version, TD build used, sha256). The exact TD command-line or automation mechanism is **unproven**; proving it is Phase 1 spike S2.
3. **Dev mode:** DATs reference `src/` files through the `file` parameter for live editing. Release mode embeds the file contents.
4. **Tests:**
   - `tests/unit/`: stdlib `unittest` on CPython 3.11, covering protocol, policy, registry, audit, identity and approvals with no `td` import. Runs in CI.
   - `tests/td/`: an in-TD runner loads the built `.tox` into a disposable test project, runs integration tests and writes `build/td-test-results.json`. Runs locally or on a self-hosted runner, because TD licensing limits hosted CI.
   - `tools/check_docs.py`: ICM, link and ADR-status validation (exists since Phase 0).
5. **Versioning:** SemVer. The tool surface and the policy schema each carry their own version.
6. **Releases:** GitHub Releases from `main` only, after owner approval. Assets: `.tox`, `.json` manifest, changelog.

## Alternatives
Commit the `.tox` binary as source (not diffable; merge conflicts); depend on Embody for externalization (coupling; open issue #194).

## Consequences
- Building requires a TD installation. The build records the TD build number used.
- **Build on the declared minimum TD build**, because a `.tox` saved by a newer build may not load in older builds. Test on both the minimum and the latest builds.
- Any base `.toe` the builder needs is generated by script at build time, not committed as a binary input. If S2 shows that is impossible, a new ADR must govern the committed binary.
- TouchDesigner requires a license and typically an interactive, GPU-capable desktop session. A self-hosted runner therefore needs a logged-in Windows session and a licensed TD install. Hosted CI runs only the `td`-free unit tests.
