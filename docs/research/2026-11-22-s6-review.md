# S6 embedded transport: independent security and threading review record (review 4)

**Date:** 2026-11-22
**Reviewer:** a separate AI agent instance working read-only.
- **Given:** the owner's S6 requirements and the code (`pyhttp.py`, `bindverify.py`, `gate.py`, `oslisteners.py`, the tests, the S6 spike and the security model), but not the author's findings.
- **Probes:** loopback-only, on ephemeral ports. It never bound a wildcard address and never launched TouchDesigner.
- **Its own test run:** 99 tests, all transport tests passing, plus 3 `test_compat` failures. Those were caught mid-edit, while the compatibility tests were being updated by the author; the suite has passed since.

**Result:** 1 High, 4 Medium, 7 Low. **All transport findings were fixed and regression-tested** (`tests/unit/test_pyhttp.py::Review4Tests`). Both TouchDesigner modes were then re-run on the fixed code: main 66/66, conflict 4/4.

## High

| # | Finding | Disposition |
|---|---|---|
| H1 | A request that passed the gate and the kill-switch check could sit in the queue and still be **dispatched after** `suspended` was set, after the state left `SERVING`, or after `begin_close`. There was also a race between the `_closing` check and `put_nowait`. This breaks §2.4 and §8.2 | **Fixed.** `pump()` re-checks after claiming each job: not `SERVING` → `503 TDFLOW_VERIFYING`/`TDFLOW_CLOSING`; MCP while suspended → `503 SUSPENDED`; in neither case is the job dispatched. `_submit` enqueues and `begin_close` sets `_closing` under the same lock. Tests: queued job, then state change or suspend, then pump; and pump after close |

## Medium

| # | Finding | Disposition |
|---|---|---|
| M1 | `str.isdigit()` accepted non-ASCII digits (`²`), and a 5,000-digit length made `int()` raise. Either way the handler died with no response and no audit record | **Fixed.** The gate requires `[0-9]{1,10}`. Any unexpected handler exception now yields `500 INTERNAL_ERROR` and an audit record. Tests added |
| M2 | `content_type` was not sanitised (CR/LF header injection). A non-Latin-1 header value raised a non-`OSError`, so nothing was answered or audited. Dispatchers could duplicate `Content-Type`, `Date`, the request id or the security headers | **Fixed.** Every header value, including the content type, must be Latin-1 with no CR/LF/NUL; a bad content type becomes `500`. These headers are now transport-owned and dropped from dispatchers: `Content-Type`, `Date`, `X-TDflow-Request-Id` and every security header. `_reply` catches all exceptions and still audits. Tests added |
| M3 | Unauthenticated jobs (`/.well-known`, 1A `/setup/api/*` reads) shared the 32-slot main-thread queue with MCP, so a local flood could starve `/mcp` | **Fixed.** `/.well-known/tdflowmcp` is now served from the immutable snapshot on the handler thread. Unauthenticated jobs have a separate quota (default 4 pending) → `503 TDFLOW_BUSY`. Tests added. Per-source auth-fail rate limiting is not possible on loopback (every client is `127.0.0.1`); aggregated audit remains the Phase 1B design |
| M4 | If copied to production, the spike's `s6/*` methods would be unsafe (quit, a 5 s main-thread block, operator edits without policy, an agent-toggled kill switch). The bearer token was written in plaintext to `ready*.json` | **Kept spike-only** and documented as such ([spike README](../../spikes/s6/README.md)). The harness now deletes `ready*.json` after every run. `spikes/*/results/` is git-ignored (all runs actually used `.tmp/s6/`, which was already ignored). In production the kill switch is user-set only and never auto-clears, and tokens are shown once and stored as digests |

## Low

| # | Finding | Disposition |
|---|---|---|
| L1 | `Expect: 100-continue` got `100 Continue`, and malformed lines got parser `400`/`501`, even during `VERIFYING` | **Fixed.** No `100 Continue` is ever sent, and parser errors answer `503 TDFLOW_VERIFYING` outside `SERVING`. Test added |
| L2 | The body (up to 1 MiB) was read before authentication | **Fixed.** Authentication and the kill switch are checked from the headers first, then the body is read |
| L3 | `others=None` (unreadable OS table) was treated as "no other listener" | **Fixed.** `others=None` → `ambiguous`. Test added |
| L4 | Verification happened only once; a co-listener appearing later went undetected | **Fixed in the spike** (off-thread re-check every 300 frames; 8 passed in the final run) and **required for item 9**. The reviewer could not test wildcard co-binding; the author's probes established it (S6 §3.1) |
| L5 | `is_closed()` ignores handler threads that are still waiting | **Accepted.** They are daemon threads with no listener; queued jobs are failed at close and `pump` no longer dispatches after close (H1). `stats()` reports `active_connections` |
| L6 | The `Bearer` scheme was matched case-sensitively | **Fixed.** The scheme is now case-insensitive, still exactly one `Authorization` value. Test added |
| L7 | `state_fn` and `authenticator` run on handler threads; a production `state_fn` that read a TD parameter would touch TD off the main thread | **Fixed** as a documented contract (class docstring, security-model §8.3): both must be pure Python, and TD parameters are mirrored into plain attributes on the main thread |

## Test gaps raised, and their status
- **Wildcard co-bind across processes:** covered by the author's probes (S6 §3.1) and by the `port_shared` verdict test. It is not covered by a cross-process unit test, because that would need a wildcard bind.
- **Queued-then-suspended/state-change, pump after close, Unicode/over-long `Content-Length`, `Expect`, content-type and non-Latin-1 sanitising:** added (`Review4Tests`).
- **Slow body racing the reaper:** not added. The reaper is covered by `test_connection_cap_and_reaper`.

## Keep (reviewer)
- **Binding and restart:**
  - Only the literal `127.0.0.1`, with `SO_EXCLUSIVEADDRUSE` and no `SO_REUSEADDR`.
  - No DNS lookup at bind; `PORT_IN_USE` mapping.
  - Restart works even with server-side `TIME_WAIT` (the reviewer verified this).
- **Threading:** dispatch only in `pump`, behind an owner-thread guard. The job state machine is race-free: a timed-out job is never dispatched, and an outcome-unknown result is reported distinctly.
- **Gate, auth and errors:**
  - Gate-first `503`; exact Host matching (DNS rebinding rejected).
  - Duplicate-header rejection, no CORS or preflights, `Connection: close` (no pipelining surface).
  - Digest-only constant-time auth; no `Authorization`/`Cookie` reaches the dispatcher; no token in audit.
  - Stable error codes with no exception text.
- **Bounds and the bind gate:**
  - Bounded slots, queue, audit ring and linger list, a reaper, and `verify_request` limited to 127.*.
  - `BindGate`: `CLOSED` is terminal without a user action.
