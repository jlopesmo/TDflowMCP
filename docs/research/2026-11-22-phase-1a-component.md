# Phase 1A: source-first TDflowMCP.tox, in-TD tests and the embedded Setup Assistant (S2, S3, items 9–10)

**Date:** 2026-11-22 · **Build under test:** TouchDesigner **2025.32440** (minimum and tested build, owner D10).
**Status:** Executed and reviewed ([review 5](2026-11-22-phase-1a-review.md)). Final evidence is in §5.

## 1. S2: source-first build (`tools/build_tox`) — **pass**
- **Unattended build.** TouchDesigner builds the `.tox` from the text in `src/`. No committed binary input is needed: the builder project is generated by `tools/tdtoe.py`, which writes its own minimal top-level files. No Derivative sample is required.
- **Embedded content.** Eleven `tdflowmcp.*` Python modules (as Text DATs under `./src`), the extension and loader, two callback DATs, the Setup page (HTML/CSS/JS), `troubleshooting.json` and a manifest with the SHA-256 of every embedded text.
- **Custom parameters.** 15 parameters on page `TDflowMCP` ([manifest](../../src/component/manifest.json)): read-only state fields, three action pulses (Open Setup, Stop Server, Run Diagnostics), Copy Tell Agent, and Port (9480, clamped 1024–65535).
- **Recorded per build** in `build/TDflowMCP.json`: version (`0.1.0.dev1`), source digest, TD build used, minimum build, `.tox` SHA-256 and size, build time, source commit and dirty flag.
- **Reproducibility, verified with `--check-reproducible`:**
  - **Reproducible source content:** the source digest is identical across clean builds.
  - **Binary metadata that varies:** the `.tox` bytes differ between builds. Expanding two clean builds with `toeexpand` gives 133 files each. Only two differ: `.build` (TouchDesigner's build timestamp) and `TDflowMCP/local/time/cframe.ts`, the current frame of the component's playing local timeline (§4a).
  - So `.tox` SHA-256 identifies a file, and the source digest identifies its content.
- **Builder self-checks:** embedded texts match their hashes; the parameter list matches the manifest; the extension initialised with `Status = Off` and no listener.

## 2. S3: in-TouchDesigner test runner (`tests/td`) — **pass**
- **Driver.** A generated disposable project loads the built `.tox` with `loadTox`, the same load path as dropping the file into a network. It drives the component only through its parameters, plus two declared test seams (`launcher`, `clipboard_writer`) and one injected fault.
- **External probes.** At named checkpoints the external harness probes the OS socket table, LAN connects, HTTP, the gate matrix, headless Chrome and a secrets scan. Results are machine-readable: `build/td-test-results.json` (full suite) and `build/td-test-results-real_browser.json`.
- **Protecting other TouchDesigner instances:**
  - The TouchDesigner processes already running are recorded and verified untouched afterwards.
  - Only the harness's own process tree may be killed, and only on timeout. The harness aborts if a test port is busy.
- **Clean lifecycle:** startup to `Setup` in ≈ 0.36 s; shutdown confirmed by the OS table; project exit code 0 with no listener left.

## 4a. Spike S7: paused timeline
Review 5 (M2) suspected that the per-frame pump stops when the user pauses the project timeline. The in-TD suite confirmed it: the run froze, because Execute DAT `onFrameStart` and delayed `run()` calls stopped. [Spike S7](../../spikes/s7/README.md) measured the alternatives:
- A COMP with an **independent, playing `local/time`** keeps its frame callbacks running: 141 frames during a 3 s root pause, versus 1 frame for a COMP on the root timeline.
- Without `independent` the local time COMP broke frame callbacks entirely.

The component now has such a local timeline, built and checked by the builder. The in-TD suite pauses the project timeline and checks that the Setup API still answers 200. The suite's own driver uses the same technique.
