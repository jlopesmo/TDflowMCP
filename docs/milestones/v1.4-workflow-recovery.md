The owner authorized work on the Base COMP delivery and recovery workflow in [Issue #13](https://github.com/jlopesmo/TDflowMCP/issues/13). [Issue #14](https://github.com/jlopesmo/TDflowMCP/issues/14) follows after the v1.4 release gates.

## Observed baseline

The published v1.3.0 binary ran in disposable Windows TouchDesigner 2025.32440 projects. The component suite passed 161 checks. Scenario D used 10 MCP calls and two approvals to build the reusable Base COMP and its control, with the owner making the external wire. The consumer's output responded to the Amount control. The MCP suite passed 103 in-TD and 288 harness checks. It exercised experiment copy, promote, undo, discard and inert restore, durable DAT undo, the native undo-stack conflict and approval-gated project save. [Validation](../icm/validation-index.md#v14-recovery-development)

## Recovery development

Keep the mutation's `audit_seq` and pass it back to `tdflow_undo` as `expected_audit_seq`. Recovery must apply only to the caller's newest reversible change and continue to check the live target and current grants. Record the undo intent and outcome together in the audit chain. Suspend agents when a restore's effects cannot be verified. A DAT text or custom control snapshot is scoped to the target in the running component. The native undo history and these snapshots do not restore a project file.

An inert experiment records a bounded component checkpoint. The candidate verified restore after a deliberate constant-parameter defect. It refused a modified checkpoint, a dynamic input and an original whose operator identity had changed. A later runtime requires owner review of the retained copy. [Candidate validation](../icm/validation-index.md#v14-connected-workflow-candidate)

## Owner-connected delivery

Call `tdflow_get_operator` with `connectors: true` for the Base COMP and the consumer. Check the exposed Out TOP and an empty input whose peer evidence is complete. The owner connects the ports in TouchDesigner. Read the input again and verify the control changes the expected output. The disposable fixture verified the exact wire and pixel change, with no extra cooks from reading connectors. The server continues to refuse external Base COMP wiring. A product path for that mutation would need a verified boundary for callbacks and other downstream effects in the parent project.

## Remaining acceptance gates

- Obtain the owner's decision on shipping the verified owner-operated wiring fallback. Automated external wiring remains gated by a separately validated topology and execution design.
- Verify connected behavior, including control changes and expected output, and measure recovery after safe defects. Check experiment lineage, stale inputs, conflicts, audit availability, suspension, revocation, concurrent edits and recovery after a restart.
- Independently review the wiring and recovery paths. Run live client, packaged, browser, unit and CI suites. Record the release-specific compatibility decision if newer-build testing is unavailable, then follow approval, tagged build, verification and publication gates.
