## Workflow

The owner pairs the dashboard and opens **Script drafts**. They choose an agent, an exact project scope, an expiry up to two hours and the draft permissions to grant. A regular role supplies no draft permissions. The existing scoped read rules and protected areas also apply. An intended target is a non-binding path under the scope.

Agents can find family guidance, create a draft, read exact source and static diagnostics, revise against the current revision and SHA-256, compare the previous revision and submit exact text. The original author revises or submits. An agent with current read permission and a matching draft read grant can inspect records in that scope.

The owner sees the exact text, SHA-256, revision, static diagnostics and the bounded previous-revision diff. Approving and rejecting only apply to the current pending revision. Copy buttons recheck the approved revision and copy plain text or a JSON checksum manifest. Paste and activation are manual owner actions. Activation runs host-capable TouchDesigner Python, and graph Undo cannot reverse its external effects.

## Storage and limits

The workspace stores signed records in the existing private per-project credentials SQLite database under TDflowMCP's private project folder. It uses the same project identity, worker, restart, move, and claim rules. A new claim uses its own private store. The project-local audit database excludes source text, diffs, titles and source hashes. Audit events identify the draft and revision when applicable. Keep the private database private. Owners can read the exported source and manifest in a plain text editor and verify the SHA-256 of the UTF-8/LF source independently.

Each project supports 32 drafts and 64 temporary grants, with up to eight drafts per author. Each draft can reach revision 100 and carries the current and immediately preceding source. Each source is capped at 12 KiB and 400 lines, and the diff is capped at 8 KiB and 80 lines. Disallowed control characters and non-LF newlines are rejected. Requests are capped per principal and per project. The owner can explicitly discard an exact draft and its preceding revision to free capacity. Audit retains the discard event. The workspace keeps no older revision history.

Bounded AST diagnostics check syntax only. Family templates describe the documented callback entry point and provide static guidance. The workspace does not resolve imports, validate callback outputs, or run candidate code. ## Security and release gates

The draft route uses the current agent or paired owner session, current grant, protected metadata and durable audit. The source never reaches the TouchDesigner adapter. A failed audit or storage operation pauses the workspace. Grant and revoke events preserve the affected agent, scope, exact permissions and expiry. Existing executable operator denials and Code Mode limits continue to apply.

Test the packaged workflow and passive native observations with disposable TouchDesigner projects. Test the paired browser, real Claude Code and Codex transport, lifecycle and negative cases, and Windows/Ubuntu CI. Independent code and security reviews must complete before owner release review.
