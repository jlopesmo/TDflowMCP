# MCP tool surface

**Status:** the 14 core tools plus `tdflow_session_note` and `tdflow_session_list` are **implemented in Phase 1B** (tool-surface version `1`). They are registered in [`src/tdflowmcp/tools.py`](../../src/tdflowmcp/tools.py), executed by [`src/td_adapter/tdops.py`](../../src/td_adapter/tdops.py), and verified in TouchDesigner 2025.32440 by the Phase 1B acceptance suite. They follow the Conditionally Accepted [ADR-0009](../decisions/0009-permission-model.md). **Phase 2A increment 1 adds four memory tools** (`tdflow_task_list`, `tdflow_task_checkpoint`, `tdflow_handoff_create`, `tdflow_handoff_resume`; additive, so the version stays `1`), verified by the in-TD memory suite. Other later-phase tools remain proposals. Names use the `tdflow_` prefix so they don't collide with other TD MCP servers a client may have loaded. Every tool declares its required actions and target resolver, using the [action classification](security-model.md#33-action-classification-of-tool-effects-security-critical).

`tdflow_approval_status` (**Phase 2B, implemented**): read-only state of one of the caller's own approval requests. Never executes anything; an approved call runs when the agent repeats it identically. Errors added in 2B: `APPROVAL_REQUIRED` (nothing ran; a request is waiting), `APPROVAL_PENDING`, `APPROVAL_DENIED`, `APPROVAL_TARGETS_CHANGED`, `APPROVAL_POLICY_CHANGED`, `APPROVAL_MISMATCH`, `APPROVAL_INVALID`, `APPROVAL_QUEUE_FULL`, `APPROVAL_REFUSED`. `tdflow_set_parameters` sets `expressions` after approval.

The v1.1 authoring workflow reports `PYTHON_SYNTAX` with location where available, `REFERENCE_NOT_FOUND` for missing literal operator references, `DAT_TEXT_CHANGED` when a source hash is stale, and `CALLBACK_ACTIVE` when editing requires deactivation first. `DAT_SOURCE_UNAVAILABLE` directs the caller to authored source or the owner's TouchDesigner view. Activation and trigger changes show the current callback source to the owner. Script CHOP, SOP and TOP creation remains unavailable. See the [v1.1 record](../milestones/v1.1-developer-capabilities.md) for verification status.

`tdflow_execute_script` (**Phase 3, implemented**, Code Mode, [ADR-0004](../decisions/0004-code-mode-strategy.md)): **off until the user turns it on** on the dashboard (not listed, `CODE_MODE_OFF`). Arguments `scope` (a COMP path) and `code` (at most 20 000 characters). Classified as **execute on `scope`**, so it needs the operator role and always the user's approval of the exact text (A1; the approval binds the script's SHA-256). The script runs on the HTTP handler thread, never on TouchDesigner's main thread, with restricted builtins. Refused before a request is made: `import`, `try`/`with`, classes, generators, lambdas, attributes starting with `_`, assignment to attributes, and names such as `exec`, `eval`, `open`, `getattr`, `type`. Its only access is the `tdflow` facade: `tdflow.<tool>(**args)` for the path-scoped operator tools (list, get, parameters, create, delete, connect, disconnect, DAT text, errors, describe network; not undo, memory, project or script tools), each a normal engine call under the agent's identity (scopes, hard denies, kill switch, intent and outcome per call). The engine checks per call that path-like arguments lie inside `scope` (`SCOPE_OUTSIDE_SCRIPT`, audited as a denial); calls that need approval on their own are refused (`APPROVAL_REQUIRED_IN_SCRIPT`); scripts cannot start scripts. Budgets: 200 facade calls, 20 s, checked between calls and by a line tracer that also stops the script when agents are suspended (`BUDGET_EXCEEDED`; a single long builtin call is not interruptible). Returns `result`, `output` (print), `calls`, `log` (per call: tool, ok, code, `audit_seq`), `script_sha256`. Not undoable as a whole; the changes it made are ordinary audited changes. **Not a sandbox**: the approval text says approved code has full access to TouchDesigner. The tool is additive, so `tool_surface_version` stays `1` (Skill 1.4 describes it).

`tdflow_describe_network` (**Phase 4, implemented**; dogfood 1 finding 5): read on `path/*` (a COMP; results filtered to what the caller can read). One network level in one call: per operator type, family, inputs, flags, errors and warnings, TouchDesigner's own `cook_count` and last `cook_ms`; `edges`, `by_family`, `with_errors`, `never_cooked`; and heuristic `hints` (`slow_cook`, `frame_budget`, `large_texture`, `error`, `dead_end`), each with its reason. The `large_texture` hint reads resolution only on an eligible owner-locked TOP. At most 300 operators (`truncated`). Tool-surface version stays `1`.

**Repository mode (2A increment 3).** The four memory tools work unchanged when the user moved project memory to a folder of the project; answers carry `memory.authority` (`embedded` or `repo`) and, for `repo`, `memory.folder` (relative, never an absolute path). Writing then needs the capability `memory:repo:write` (`DENIED`, rule `M8` without it); `tdflow_whoami` reports `memory.repository_write`. New error: `MEMORY_LINK_MISMATCH` (the linked folder belongs to another project; rule `M7`). An unlinked, missing or stale folder answers `MEMORY_UNAVAILABLE` (rule `M7`) with the precise reason in the message. `MEMORY_MODE_UNSUPPORTED` is no longer returned.

Errors added in 2A: `MEMORY_UNAVAILABLE` (no, an uninitialised, or more than one `tdflowProject`; M2), `MEMORY_READ_ONLY` (records do not match the audit ledger; the user must Claim Project Memory; M5), `MEMORY_CONFLICT` (stale `based_on_rev`, or a write between plan and execute), `MEMORY_NOT_FOUND`, `MEMORY_FULL`. Memory writes are not undoable (records are append-only). The four tools are additive, so `tool_surface_version` stays `1` (Skill 1.1 describes them).

## Conventions

- **Versioning:** additive, backward-compatible changes (new optional arguments, new output fields) do not change `tool_surface_version`. Removing or renaming a tool, argument or field, or changing a meaning, bumps it.

- Results return both human-readable `content` and machine-readable `structuredContent` with an `outputSchema`.
- Errors are tool results with `isError: true` and a stable `code` (`DENIED`, `NOT_FOUND`, `INVALID_ARGS`, `BUDGET_EXCEEDED`, `APPROVAL_UNAVAILABLE`, `UNDO_CONFLICT`, `AUDIT_UNAVAILABLE`, `SUSPENDED`, `MCP_DISABLED`, `MEMORY_CONFLICT`, …). Protocol errors use JSON-RPC errors.
- `TDFLOW_NOT_COOKING` (2026-11-23, [S9](../research/2026-11-23-s9-minimized-window.md)): TouchDesigner is not running frames, usually because its window is minimized. Any tool that needs TouchDesigner's main thread answers with it at once; nothing ran, and the call may be retried after the user restores the window. `tdflow_whoami`, `tdflow_session_note` and `tdflow_session_list` need no frames.
- Every mutating result includes `audit_seq` and `undo_label`.
- `tools/list` returns only the tools the calling agent has *some* grant for (progressive disclosure, fewer tokens). Policy is still enforced at call time.
